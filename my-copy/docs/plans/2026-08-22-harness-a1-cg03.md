# Read-only cache audit adapter and automation-safe CLI

## Knowledge packet

- MENTAL_MODEL: 読み取り専用の証拠経路は「writeしない予定」ではなく、client能力・query shape・実DB不変・CLI exit/stdoutの全境界で証明する。人間向け出力と機械向けJSONはnpm wrapperを含めて異なる契約として扱う。
- ASSIGNED_TEST_EVIDENCE: A1-CG3-T1は単1の最小`findMany`・半開区間・成否に関わらないdisconnect・存在しないDBの非生成を固定し、T2はoption error・duplicate/idempotent・child JSON purity・query failure・human label・unsupported success・overflow failureを固定し、T3は実package commandによるdisposable SQLite不変を固定した。v2のT3がtest-only loglevelでnpm bannerを隠したため、v3でexact `npm run --silent`へ修正した。
- PROBLEM_CONTEXT: pure集計が正しくても、通常のPrisma singleton、raw SQL、書込み可能なSQLite open、不安定なstdoutを介したら定期監査の安全性と自動化可能性は証明できない。npm自身がchildより先にlifecycle bannerをstdoutへ出すことも、JSON consumerには契約違反になる。
- EXECUTION_FLOW: CLI引数をDB access前にparseする→validなJST週を確定する→`readonly=true/fileMustExist=true`専用adapterを作る→`startedAt >= start` / `< end`の1回だけの最小`findMany`を実行する→`finally`でdisconnectする→pure reportをhumanまたはJSONで出す→query/option/aggregate errorをstable stderrとnonzero exitにする。packageの機械向け呼び出しだけは`npm run --silent`を使う。
- CODE_EVIDENCE: `src/lib/harness-cache-audit-query.ts:createReadonlyHarnessAuditClient`がPrisma Better SQLiteの読み取りopenを、`queryHarnessCacheAudit`が単1queryと`finally` disposalを固定する。`src/lib/harness-cache-audit-cli.ts:runHarnessCacheAuditCli`がoption/query/overflowのexitと出力を分離し、`scripts/audit-harness-cache.ts`と`package.json` がpackage entryを提供する。`src/lib/harness-cache-audit-cli.test.ts`がfake adapterと実SQLiteの両方を検証する。
- DESIGN_RATIONALE: 既存の一般用DB singletonをimportせず、監査の入口でSQLiteをread-only/file-must-existにすると、呼び出し側の意図ではなくadapter能力と実測hashの両方で非書込みを検証できる。CLI runnerへdependencyを注入し、child JSON purityとnpm package boundaryを別testにすることで責任範囲を混ぜない。
- REJECTED_ALTERNATIVES: `src/lib/db.ts`の共用clientは読み取り能力を強制できないため却下。raw SQLはPrismaの最小select契約を迂回するため却下。非静粛npm呼び出しにtestだけ`npm_config_loglevel=silent`を注入する案はユーザー向けコマンドを証明しないため却下。DB hashだけの比較はWAL/SHM/journalの副作用を見逃すため却下。
- GUARANTEES: 専用clientは`PrismaBetterSqlite3({url, readonly:true, fileMustExist:true})`を使い、HarnessRunを1回だけ最小列で半開区間queryし、常にdisconnectする。stable option/query/overflow exit、unsupported/invalid/no-sample単独の成功、child JSON 1文書、正規の`npm run --silent`全stdout 1文書、disposable DB hashとsidecar set不変、missing DB非生成を実行testが保証する。
- NON_GUARANTEES: production DBの書込み可能性全般、通信障害、schema完全性、stored row修正、backfill、collector、production metric、UI、LoopJob/worker/watchdog/scheduler、launchd定期実行、Issue #24全体の完了は保証しない。
- CONCRETE_TRACE: temp DBにW34内のClaude `10/30/10`、Codex `100/80/0`とend-exclusiveの1行を入れ、DB hashと`-wal/-shm/-journal`隣接setを取る。`npm run --silent harness:audit-cache -- --week 2026-W34 --json`は2行だけを読み、stdout全体が1 JSON文書になり、終了後のhash/sidecar setは開始前と一致する。存在しないDB URLは`query_failed`でnonzeroになりファイルを作らない。
- CONCEPT_DELTA: 「SELECTだけ書けばread-only、childがJSONだけ出せばpackageもJSON」から、「adapter open権限・query shape・DB/sidecar不変・child出力・npm wrapper出力を別々に証明する」へ更新した。
