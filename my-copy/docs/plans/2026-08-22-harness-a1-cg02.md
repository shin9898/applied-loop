# JST week cohort and safe cache aggregation

## Knowledge packet

- MENTAL_MODEL: 監査cohortをtimezoneに依存しない厳密な半開区間へ先に固定し、互換性のあるprovider semanticsだけを分離集計する。除外とoverflowは消さず、信頼できない合計と従属率を`null`にする。
- ASSIGNED_TEST_EVIDENCE: A1-CG2-T1はJST月曜始まりのISO week、年界、53週の成立/不成立を固定し、T2はprovider別segment・除外理由・unknown harness・ソート・null rateを固定し、T3は8つの集計overflow pathと安全な隣接値の保持をREDからGREENへ固定した。
- PROBLEM_CONTEXT: 異なる週境界・provider semantics・無効行を一つの率へ混ぜると、cache改善がないのに改善したように見える。JavaScriptの安全整数上限を超える累積も、throwや丸めではなく判定不能として可視化する必要がある。
- EXECUTION_FLOW: `YYYY-Www`を厳密parseする→Asia/Tokyoの月曜00:00をUTCの`startInclusive/endExclusive`へ変換する→各raw行をCG-01で正規化する→known providerごとにchecked-addする→invalid/no-sample/unsupportedを理由別に数える→安全な合計だけで率を出し、固定順でreportする。
- CODE_EVIDENCE: `src/lib/harness-cache-audit.ts:parseHarnessAuditWeek`がstrict ISO-week windowを、`checkedAggregateAdd`と`calculationErrors`が8つの安全整数境界を、`buildHarnessCacheAuditReport`がprovider分離・除外・決定的順序を固定する。`src/lib/harness-cache-audit.test.ts`が3つの割当testを保持する。
- DESIGN_RATIONALE: DBやCLIから切り離したpure report builderにすることで、同じrowsから常に同じsegment・除外・error順を再現できる。overflowしたfieldだけでなくそのfieldに依存するrateを`null`にし、安全な兄弟fieldは残す設計で証拠を最大限保存した。
- REJECTED_ALTERNATIVES: locale/date-library既定値に週境界を委ねる案は実行環境差を持ち込むため却下。unknown/invalid行を黙って捨てる案は欠測率を見えなくするため却下。overflowを`Infinity`・丸め・上限値にする案とsegment全体を丸ごと破棄する案は、それぞれ偽の数値と安全な証拠喪失を生むため却下。
- GUARANTEES: `2026-W34`が`[2026-08-16T15:00:00.000Z, 2026-08-23T15:00:00.000Z)`になるJST週境界、ISO年界、providerごとのsegment分離、除外理由の可視性、code-unit lexical順、zero denominatorのnull、8つのaggregate overflow pathと従属nullを実行testが保証する。
- NON_GUARANTEES: DBからの取得、CLI引数とexit code、標準出力の純度、DB不変、過去データ修正、provider/model/repo/fingerprint跨ぎの比較、production metric切替は保証しない。
- CONCRETE_TRACE: `2026-W34`はJSTの2026-08-17月曜00:00から2026-08-24月曜00:00までに限定される。Claudeの`10/30/10`行はnormalized total 50、read 30、reuse 0.6になり、負のClaude行は`negative_input`で別カウントされる。Codexのread-over-total、zero-total、非0 writeは各理由で除外され、同じsegmentの率へ混ざらない。
- CONCEPT_DELTA: 「取得行をすべて合計して1率を出す」から、「週とsemanticsを先に境界化し、除外と計算不能をreportの一級証拠にする」へ更新した。
