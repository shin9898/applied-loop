# Provider-aware cache usage normalization

## Knowledge packet

- MENTAL_MODEL: 同じ列名でもproviderごとに数値の関係が違う。率を計算する前にusage semanticsを選び、観測できない値は`null`、不正・未対応な証拠は理由付きoutcomeとして残す。
- ASSIGNED_TEST_EVIDENCE: A1-CG1-T1はClaudeとCodexの回帰fixture・zero-totalを固定し、T2はCodexの非0 `cacheCreate`とread-over-totalの優先順を固定し、T3はfield/predicate順・unknown harnessより先の数値検証・checked addition・入力不変をREDからGREENへ固定した。
- PROBLEM_CONTEXT: 従来の共通式`cacheRead / (tokensIn + cacheRead + cacheCreate)`は、Claudeの別カウンタには合うが、Codexの`tokensIn`に内数として含まれる`cacheRead`を二重計上する。provider横断で一つの分母を使うとcache再利用性の判定自体が誤る。
- EXECUTION_FLOW: raw四値をsnapshotする→`tokensIn` / `cacheRead` / `cacheCreate`を固定順で検証する→harnessを判定する→provider固有の不変条件とoverflowを検証する→`supported` / `no_sample` / `invalid` / `unsupported`の判別可能な証拠を返す。
- CODE_EVIDENCE: `src/lib/harness-usage-normalization.ts:validateCounter`が数値検証の優先順を、`checkedAdd`が安全整数overflowを、`normalizeHarnessUsage`がprovider別正規化と結果状態を固定する。`src/lib/harness-usage-normalization.test.ts`が3つの割当testを保持する。
- DESIGN_RATIONALE: raw行を書き換えないpure normalizerに封じ込めることで、provider semanticsを呼び出し側の推測から切り離し、後方互換のlegacy値と新しいnormalized値を同じraw evidenceから比較できるようにした。
- REJECTED_ALTERNATIVES: 共通分母はCodex readを二重計上するため却下。Codexの保存値0を「writeを0と観測」とみなす案は観測不能を事実化するため却下。負値・read-over-total・overflowを0や上限にclampする案はcollector障害を正常値に見せるため却下。
- GUARANTEES: `harness-usage-v1`のClaude/Codex計算、zero-totalのno-sample、固定validation precedence、Codex writeの`null`、非0 Codex `cacheCreate`のunsupported、row内の安全整数算術、raw入力不変を実行testが保証する。
- NON_GUARANTEES: 既存のproduction metricは切り替えない。DB行、過去データ、collector、週集計、UI、LoopJob、provider APIのtelemetry capabilityを変更・保証しない。
- CONCRETE_TRACE: Codex行`tokensIn=1549716286, cacheRead=1490230656, cacheCreate=0`は、total `1549716286`、read `1490230656`、fresh `59485630`、write `null`、normalized reuse約0.961615になる。legacy式はreadを分母へ再加算するため約0.490216に低下する。
- CONCEPT_DELTA: 「3カウンタは全harnessで同じ形」から、「raw値を消さずproviderの算術関係を先に選び、不明と不正を率に変換しない」へ更新した。
