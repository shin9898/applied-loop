# LoopJob state integrity and dedupe

## Knowledge packet

- MENTAL_MODEL: durable work is accepted only after a closed registry validates the exact payload shape; identity, canonical bytes, dedupe, and legal state shape are derived by the harness rather than supplied by a caller.
- ASSIGNED_TEST_EVIDENCE: `A2-CG1-T1 state-machine-table` first failed because `./state-machine` did not exist. Its five nested cases now prove strict canonical payloads, create-first targeted `P2002`, due ordering and deterministic backoff, direct CHECK rejection, and synchronized same/different-hash enqueue races. The focused gate is 6/6 GREEN and the project suite is 364/364 GREEN.
- PROBLEM_CONTEXT: an asynchronous learning loop needs durable jobs without persisting arbitrary prompts, answers, commands, or caller-chosen dedupe keys. A pre-read followed by insert would race, while a permissive row shape could create states that no worker can safely interpret.
- EXECUTION_FLOW: validate exact registered fields -> canonicalize sorted JSON -> derive payload hash and logical dedupe key -> attempt `LoopJob.create` -> on only the dedupe-key `P2002`, re-read the winner -> return untouched duplicate, typed conflict, or typed storage failure. State transitions additionally pass SQLite CHECK constraints and clear or install lease fields as one shape.
- CODE_EVIDENCE: `src/lib/loop-jobs/state-machine.ts:100` freezes the registry into a null-prototype object; `state-machine.ts:138` validates exact fields; `state-machine.ts:182` recognizes only the dedupe constraint; `state-machine.ts:285` derives and inserts the row. `prisma/migrations/20260822090000_loop_job_substrate/migration.sql:19` fixes identity, status, attempt, error, and state-shape checks; its three indexes are at line 72.
- DESIGN_RATIONALE: create-first lets the unique index decide the race, then a targeted re-read distinguishes an identical logical job from a hash conflict without overwriting either payload. Explicit timestamps and DB checks make illegal states fail at the storage boundary while TypeScript keeps callers on the closed path.
- REJECTED_ALTERNATIVES: caller-supplied dedupe keys were rejected because they can contain sensitive/free-form material and silently alias jobs. Read-before-create was rejected because two writers can both observe absence. Upsert was rejected because it can reset attempts, timestamps, payload, or terminal state. Free-form payload JSON was rejected because validation after persistence is too late.
- GUARANTEES: exact registered payloads only; canonical JSON/hash; internally derived IDs and dedupe key; same-key/same-hash returns the untouched winner; same-key/different-hash returns `dedupe_payload_conflict`; due ordering is deterministic; attempts increment only on a won claim; terminal rows are retained and cannot be reclaimed; invalid direct state shapes fail CHECK constraints.
- NON_GUARANTEES: this gate does not prove concurrent claim ownership, crash recovery, exactly-once external effects, domain-write plus enqueue atomicity, or activation. Those boundaries belong to CG-02 through CG-04 or later Issue #24 slices.
- CONCRETE_TRACE: `state_probe` with opaque entity ID, operation `inspect`, and a 64-hex artifact hash becomes sorted canonical JSON. The queue derives `state_probe:v1:<sha256 projection>`, inserts `queued/attempts=0`, and fixes all timestamps from the injected clock. A simultaneous identical enqueue loses the unique race, re-reads that key, observes the same payload hash, and returns the original row without changing `maxAttempts`, timestamps, payload, or state.
- CONCEPT_DELTA: the model changed from “a queue row is arbitrary JSON plus a status” to “the registry and unique storage boundary jointly define which bytes and transitions can exist; duplicate detection never grants overwrite authority.”
