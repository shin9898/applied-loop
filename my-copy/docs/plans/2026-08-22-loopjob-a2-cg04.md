# LoopJob dormant worker authorization and database isolation

## Knowledge packet

- MENTAL_MODEL: merely installing queue code must not grant it a database or an execution path. Native phase 1 proves exact invocation and target identity before any TypeScript loader, Prisma module, database open, recovery, or claim becomes reachable.
- ASSIGNED_TEST_EVIDENCE: `A2-CG4-T1 dormant-worker-and-disposable-db` first failed because the package command, native worker entry, and enabled one-shot behavior were absent. Its four nested cases now prove precedence/import poison and canonical URL rejection, artifact-only migration and adapter runtime, one-shot at-most-one claim, and base source plus DB/build isolation. The focused gate is 5/5 GREEN and the project suite is 364/364 GREEN.
- PROBLEM_CONTEXT: existing `src/lib/db.ts` falls back to a developer DB, while loaders and imports can execute code before application checks. A nominally disabled worker that imports Prisma first, accepts ambiguous file URLs, or falls back to `DATABASE_URL` could create/open the wrong database during tests, build, setup, or an accidental command.
- EXECUTION_FLOW: native Node entry receives argv/env -> reject unless argv is exactly `--once` and enable flag is exactly `1` -> parse and round-trip one canonical absolute local `file:` URL -> require the decoded path to be an existing regular file -> only then spawn the TypeScript phase 2 with the decoded path -> use `fileMustExist` and one-shot recovery plus at-most-one claim -> emit one closed JSON code and exit.
- CODE_EVIDENCE: `src/lib/loop-jobs/worker-phase1.mjs:5` fixes precedence and the URL/path round-trip; line 40 checks the existing regular file. `src/lib/loop-jobs/worker.mjs:11` keeps authorization before the TS loader barrier. `src/lib/loop-jobs/worker-phase2.ts:17` uses the decoded path with `fileMustExist`, an empty production registry, one recovery, and one delivery. `package.json` exposes only the manual `loop:worker` command.
- DESIGN_RATIONALE: a dependency-free phase 1 makes “disabled” mechanically testable even if Prisma or the loader is poisoned. Exact URL round-trip removes alternate spellings and authority ambiguity. Requiring an existing file and no fallback makes target selection explicit and prevents accidental database creation.
- REJECTED_ALTERNATIVES: checking the enable flag after importing TypeScript/Prisma was rejected because imports cross the trust boundary first. Reusing global `src/lib/db.ts` was rejected because it has a default developer DB. Accepting relative paths or `file:./...` was rejected because cwd changes identity. A daemon loop, launchd job, app startup hook, or `after()` wiring was rejected because A2 is substrate-only and default-off.
- GUARANTEES: without either opt-in the worker exits before phase 2; malformed, noncanonical, authority-bearing, memory, missing, or alternate URLs fail closed without file creation; accepted encoded-space URL opens the intended existing file; phase 1 imports only Node built-ins; one invocation recovers and claims at most one job; automation output is one JSON document; build/setup/tests/app paths do not invoke the worker; base application source and protected DBs remain unchanged.
- NON_GUARANTEES: A2 does not install or schedule the worker, provide a daemon/watchdog/heartbeat, register real handlers, enqueue domain work, activate shadow evaluation, apply the migration to a live DB, or prove later operational SLOs.
- CONCRETE_TRACE: `npm run --silent loop:worker -- --once` with enable `1` and canonical `file:///tmp/worker%20target.db` passes raw URL, decoded path, and existing-file checks. Phase 2 receives `/tmp/worker target.db`, opens it with `fileMustExist`, finds an empty queue, emits exactly `{"code":"no_job"}`, and exits zero. Removing the enable flag returns `worker_disabled` before the phase-2 module can resolve.
- CONCEPT_DELTA: the model changed from “the worker is safe because nobody calls it” to “the worker has no authority until two explicit opt-ins and an exact existing DB identity pass a dependency-free barrier.”
