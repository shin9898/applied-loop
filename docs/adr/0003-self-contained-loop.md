# ADR-0003: ループはアプリ内で完結させ、外部ワークフロー依存を脱する

## 背景

MVP 時点のデータソースは開発者個人のローカルワークフローに依存していた。

- 学び・適用記録: `~/.my-copy/pm-learn/entries.jsonl` のインポート
- 復習カード: `~/.claude/learning/sr-cards.json` のインポート
- 週次ふりかえり: koki-central (Obsidian) への投影スクリプト

このままでは workbench 相当の仕組みを持たないユーザーは
何もデータがない空のアプリを開くだけで、価値を体験できない。

## 決定

「学び → 適用 → 復習 → 証跡」のループはアプリ内だけで完結させる。
外部ワークフローとの連携は「移行・オプション機能」に格下げする。

具体的には:

1. 学びの登録・適用記録はアプリ内フォームが第一の入力経路
2. 適用記録から復習カードを自動提案する（記録時に
   「この学びをカードにしますか?」→ 穴埋め文を下書き生成）
3. 空の状態はすべてオンボーディング導線にする
   （「最初の1冊を登録しよう」のガイド付き）
4. 週次ふりかえりはアプリ内ビューとして実装し、
   koki-central への投影は開発者個人用のオプションとする

## 理由

- 「適用証跡に特化した学習ループ」という価値は外部ツールなしでも成立する。
  依存していたのは実装の手順（既存データで試したかった）であって、
  プロダクトの本質ではない
- 公開を目指す以上、初回体験が空のアプリでは誰も定着しない。
  空の状態 = オンボーディングは Soft SaaS の基本原則
- 却下案: 「外部連携を必須にして対象ユーザーを開発者に絞る」
  → 市場が狭く、連携の保守コストが価値創造を上回るため

## 結果・トレードオフ

- 得られるもの: 誰でも始められる / 公開可能なプロダクト / ループの自己完結
- 失うもの: なし。既存インポーターは移行機能として残す
