# ADR-0020: 日次振り返り型ナレッジループ（材料無制限 → 教科書 → 多状態）

## 背景

AI 実装速度が上がると、commit ごと・その場しれん消化は必ず破綻する。

実測 (2026-08-10):

- `GATE_BACKLOG_CAP = 5` により pending しれんが閾値を超えると、新規 commit は `skipReason=backlog` で**出題生成だけ止まる**
- 監視中 repo からの DevEvent は届いている（例: 当日 19 件受信・fired 0）
- 一方で未回答しれん・未仕分け受信箱・目標証跡ゼロが並存し、「動いていない」ように見える

件数制限で供給を黙らせるのは、今の開発速度では再発が構造的。  
必要なのは **全部貯めて、日次で圧縮し、理解状態ごとに翌日を進める**形。

## 決定

### 1. コア一文（0019 を更新）

> 実装の足跡（commit / セッション学び）を漏れなく材料として貯め、1日の終わりに教科書へ圧縮し、確認テストで理解状態を振り分けて翌日の振り返りを進めるローカル学習ループ。

UI は Living Atlas のまま。操作の正典は MCP + Web。

### 2. 層を分ける（混ぜない）

| 層 | 何か | 件数制限 |
|---|---|---|
| **材料 (Material)** | commit イベント、学び候補、論点カード | **なし**（欠落禁止） |
| **教科書 (Textbook)** | その日の材料を章立てした HTML（＋必要なら MD） | 1日1本（再生成可） |
| **確認 (Check)** | 教科書から蒸留した少数の確認問い | 日次で少数（目安 3〜7） |
| **理解状態 (Mastery)** | 確認後の振り分け | 状態ごとに翌日導線 |

**しれん即時生成は本線ではない。**  
commit → すぐ Gate(pending) は、過渡期の互換経路として残してよいが、既定の価値提供は日次振り返り。

### 3. 理解ステータス（2値を捨てる）

採点の `passed` / `failed` は内部の生結果として残してよい。  
ユーザー向け・翌日導線の正本は次の4状態:

| ステータス | 意味 | その後 |
|---|---|---|
| `clear` | 説明でき、別状況にも転用できる | 間隔を空けた再確認。ずかんから外す／resolved |
| `partial` | 概ね分かるが穴がある | 教科書の該当節 + 小さな再問 |
| `stuck` | つまずき・誤解が残る | ずかん本線、根拠リソース、再出題 |
| `parked` | 今日は扱わない | 翌日以降の候補に残す（量過多の逃がし弁） |

6値以上は運用コストが増えるので採用しない（必要なら後で `clear` を細分化）。

### 4. 日次ループ

```text
一日の実装
  → Material を無制限に蓄積（hook / capture_* / 既存 DevEvent）
夜 or 朝の振り返り
  → その日の Material から Textbook HTML を生成
  → 少数 Check を出題
  → Mastery を付与（clear / partial / stuck / parked）
  → ステータス別キューが翌日の briefing / ちず CTA になる
```

Textbook の正本は DB 上の材料・章データ。HTML は**その日のビュー**（配布・読み返し用）。HTML だけを正典にしない。

### 5. backlog cap の扱い

- **Material 蓄積を cap で止めない**（`backlog` で DevEvent を捨てる／生成スキップして材料を失う、をやめる）
- 過渡期: `GATE_BACKLOG_CAP` は「即時しれん生成」にだけ効かせるなら残してよいが、既定 UX は日次 Check
- 最終形: 即時しれん生成をオプトイン or 廃止し、Check は Textbook 蒸留からのみ

### 6. コンテキスト溢れ防止（必須・最優先品質）

材料を無制限に貯める以上、**いちばんまずい失敗は「全部載せようとして LLM が読み切れず、黙って漏れる」**こと。  
cap で材料を捨てるのは禁止。代わりに **階層と予算**で読む量を制御する。

| 層 | LLM / 人に渡す量 | 禁止 |
|---|---|---|
| Material（DB） | 全量保持。一覧は要約・件数のみ | 生 DevEvent 全件をプロンプトに貼る |
| Textbook 生成 | 日次バッチが材料を**章へ圧縮**してから書く | 材料 JSON を丸ごと HTML にダンプ |
| じゅもん注入 | **いま開いている1章**＋ひとこと＋一次情報の **URL 一覧**＋深さ | その日の全章・全 commit diff 本文を注入 |
| Check | 教科書から蒸留した **3〜7問** | 材料件数に比例して問いを増やす |
| 翌日 CTA | Mastery 別の少数キュー | open な全ナレッジを briefing に列挙 |

設計ルール:

1. **リンク先送り** — diff / 公式 doc は URL を渡し、本文はモデルが必要分だけ取る（注入はポインタ）。
2. **章予算** — 1章の本文・注入は上限（目安: 本文短文＋箇条書き数点＋URL 数点）。超える材料は「関連材料 N 件」に畳み、`parked` または翌章候補へ。
3. **日次の章数上限** — 多すぎる日は章を増やしすぎない（目安 3〜5）。残りは「今日扱わない」枠（Mastery `parked` / 翌日 Textbook）。
4. **漏れたら検知** — Textbook 生成ログに「圧縮で落とした材料 ID」を残す。黙って消さない。
5. **検索で戻る** — 全量コンテキストの代わりに、章外は `find_related_learnings` 等の検索で都度引く。
6. **章コピーの多様性** — 章が2つ以上あるとき、title / oneLiner / body / BAD・OK / why / practice は材料に応じて互いに異なること。共通テンプレ文だけで章を埋めてはならない（`chaptersHaveDistinctCopy` で回帰固定。UI も diagramKind 共通文面にフォールバックしない）。
7. **章レッスンスロット必須** — 新規生成も再生成も同一の規則パイプラインで、各章を物語順に埋める: `work`（いま進めていた改修）→ `timing`（ナレッジが溜まったタイミング）→ `action`（とった対応）→ `why`（その理由）→ `practice` / `consequence` / `alternative`（一般化）と選定対比の BAD/OK。マーカーは `bodyDeep`（`[[WORK]]` / `[[TIMING]]` / `[[ACTION]]` / `[[WHY]]` 等）。欠落は生成失敗。
8. **LLM 研磨は章単位オプトイン** — 「手元で再圧縮」は LLM なし。任意の「この章をLLMで磨く」だけがヘッドレスで1章分を厚くする。入力は当該章の要約・既存スロット・evidence のみ（日次全量・diff 全文禁止）。失敗時は規則文を維持。

### 7. 0019 / 0006 との関係

- ADR-0019 の「コミットのたびにしれん」コア一文は、本 ADR のコア一文に**更新**する（追記で明示）
- ADR-0006 のイベント収集・Bearer・ローカル採点は維持。変えるのは**発火タイミングとユーザー向け状態モデル**
- P0–P3（渡せる土台〜同僚完走）の完了物は捨てない。P4 として本ループへ重心移動する

### 8. Won't（本 ADR 拘束）

- SaaS / マルチユーザー
- 教材コースの手書き大量生産（Textbook は自分の材料の圧縮）
- 確認問いの無制限同時提示（また backlog になる）
- HTML だけを正本にする
- ステータスを合否2値に戻す
- **日次全材料・全 diff をじゅもん／Check のコンテキストに載せる**（溢れ＝黙過漏えい）

## 理由

- AI 時代のボトルネックは「材料不足」ではなく「圧縮と振り返りの欠如」
- 件数制限は安全装置に見えて、実装が多い人ほど学習ループを殺す
- 2値（CLEAR/miss）は部分理解と「今日はやらない」を表現できない
- 日次1教科書は、DQ 世界観（ぼうけんのしょ）とも両立する

却下した案:

| 案 | 却下理由 |
|---|---|
| cap を大きい数字にするだけ | 本質が残る。溜まる側が死ぬだけ遅延する |
| commit 毎しれんを維持しつつ全部解かせる | 速度に負け続ける |
| ステータスを細かく10段階 | 振り分けコストが振り返りを殺す |

## 結果・トレードオフ

得られるもの:

- 実装が多い日ほど材料が豊かになる（止まらない）
- 振り返りの儀式が明確（教科書 → 確認 → 振り分け）
- 翌日 CTA が状態別になる

失うもの / コスト:

- 「commit した瞬間にしれんが1問」体験は弱まる（オプトインで残せる）
- Textbook 生成・章立ての実装と評価が必要
- Gate スキーマ／UI に Mastery 4状態の導入が必要

## 実装スライス（進捗は phase-progress P4）

1. Material 経路: DevEvent / Capture を cap で落とさない
2. Textbook: 日次生成 API + `docs` or `public/retro/` HTML 出力規約
3. Check: 教科書からの少数出題
4. Mastery 4状態 + ずかん／briefing 導線
5. 移行: 既存 pending しれんの消化 UI（parked / dismiss）と説明コピー
6. **じゅもん（AIと対話して深掘り / ADR-0015 再利用）**: 教科書の「読む」面に `TerminalPanel` を載せる。UI 表記は DQ 語＋括弧補足（例: 「じゅもんをとなえる（AIを開く）」）。注入は **開いている1章だけ**（ひとこと・一次情報 URL・深さ）。日次全量・diff 本文は入れない（§6）。確認モード中は閉じる。学びが残れば `capture_learning_candidate`
7. **コンテキスト予算の実装**: Textbook 生成・じゅもん注入・Check 蒸留に上限と「圧縮で落とした材料」の証跡を入れる（§6）
8. **レッスンスロット＋任意研磨**: 新規／再生成とも規則で why/practice/consequence/alternative を必須化。章単位 `polishTextbookChapter` はオプトイン（§6.7–6.8）
