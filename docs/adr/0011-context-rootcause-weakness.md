# ADR-0011: ゲートの文脈再現・誤解の根因分類・弱点パターン

## 背景

product-brief v4 の E / F / H。いずれも「ゲートと誤解のデータを
もう一段活用する」拡張であり、出題・採点プロンプトの拡張で実現できる:

- E 文脈再現: ゲートが出る頃にはコミットの文脈を忘れている。
  回答前の認知負荷を下げる前提キャッチアップが必要
- F 根因分類: 誤解の質 (知識不足 / 確認不足 / 前提誤認) が分かれば
  対処 (インプット強化 / ハーネス改善 / 要件見直し) が変わる
- H 弱点パターン: ルーブリック観点別スコア (ADR-0007) を横断集計して
  「いつも欠ける観点」を可視化する

## 決定

### 1. 文脈再現 (E)

- スキーマ: `Gate.contextSummary String?`
- `generateGate` の出題 JSON に `context_summary` を追加:
  「このコミットでやったこと」の 2-3 行要約 (diff から生成)
- リソース (調べる場所) とは別物として質問の上に表示する
- 再出題ゲート (retry / sr_review) は firstGate から継承

### 2. 根因分類 (F)

- スキーマ: `Misconception.rootCause String?`
  (`knowledge` / `verification` / `premise`)
- `gradeGate` の採点 JSON に `root_cause` を追加
  (misconception がある場合のみ必須):
  - `knowledge`: 知識不足 (そもそも知らなかった)
  - `verification`: 確認不足 (AI/ハーネスの出力を鵜呑みにした)
  - `premise`: 前提の誤認 (状況理解がズレていた)
- 分類不能な場合は null を許容 (欠損扱い。推測で埋めない)
- 誤解図鑑 (/zukan) に「あなたの誤解の傾向」として
  rootCause 別の件数分布を表示 (図鑑を診断に格上げ)

### 3. 弱点パターン (H)

- `src/lib/weakness.ts` を新規作成:
  - 全ゲートの `rubricResult` を走査し、観点 (aspect) を
    正規化 (表記揺れの統合は LLM 1 回呼び出しでクラスタリング、
    週次キャッシュ) して score 0/1 の割合を集計
  - 「欠落率の高い観点」上位を返す
- ダッシュボードに「弱点パターン」セクションを追加:
  欠落率の高い観点トップ 3 と、関連する open 誤解への導線
- 観点数が少ない (ゲート採点 10 件未満) うちは表示しない
  (偽の精度感を出さない)

## 却下した案

- **根因の多値化 (複数タグ)**: 主因 1 つに絞らせる。
  曖昧さを許すと集計が意味を持たない
- **弱点クラスタリングのルールベース化**: aspect の表記揺れは
  自由記述なので機械的な正規化は破綻する。LLM クラスタリング +
  キャッシュでコスト抑制
- **文脈再現の diff 全文併記**: トークン増大と「答えが書いてある」
  問題。2-3 行の要約に限定する
