# ADR-0002: UI/UX は Pencil デザインファーストで作る

## 背景

MVP を実装ファースト（Tailwind のテンプレ的組み立て）で作った結果、
初回レビューで「センスのない仕上がり」「機能的に使いたくなるワクワク感が一切ない」
というフィードバックを受けた。記録フォームと一覧の集合 = 「台帳」止まりで、
明日も開きたい理由が体験に埋め込まれていなかった。

## 決定

UI/UX は Pencil でデザイン案を作成し、レビュー通過後に実装する。
実装ファーストで UI を作らない。

## 理由

- 「ワクワクしない」のような言語化しにくい感覚的品質は、
  テキストで詰めるより視覚案を見てレビューする方が圧倒的に速い
- ワクワク感の構成要素は4つ特定済み: 成長・証跡の可視化 / 賢い問いかけ /
  世界観・心地よさ / ループが回る実感。これらは体験設計であり、
  コンポーネント配置の問題ではない（実装前に設計対象として扱う必要がある）
- 実装コストが高い環境（Codex 委譲等）ほど手戻りが致命的だが、
  個人開発でも同じ構造で無駄になる

## 結果・トレードオフ

- デザイン工程が増えるが、実装の手戻りと「台帳化」リスクが減る
- トレードオフ: デザイン→実装の乖離（ピクセル完全一致の追求）は追わない。
  Pencil 案は体験設計の合意物であり、実装は Tailwind での近似でよい
