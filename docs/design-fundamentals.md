# Applied Loop — デザイン基礎の運用正典

研修で得た「共通の目線」を、Applied Loop の UI ブラッシュアップに使うための正典。
原本 PDF は vault/repo に置かない（CONFIDENTIAL）。原則とチェックリストのみここに置く。

Obsidian 知識ノートとも同期する。エージェントは Cursor skill `design-fundamentals` を読む。

## ページ外枠（必須）

一覧・ダッシュボード系:

```
<PageShell> … </PageShell>
```

（実装: `src/components/page-shell.tsx` → `max-w-[1312px] … px-8 py-12 md:px-16`）

詳細・長文系は `<PageShell narrow>`。  
**外枠なしの裸 `<div>` は禁止**（学び一覧で発生した崩れ）。

スペーシングは **8 の倍数**（Tailwind: 2/4/6/8…）。端数 px を増やさない。

## モーション言語（視聴者向けアプリ）

操作は主に LLM / MCP。アプリは **証跡を眺める紙**。だから入場と気配で「台帳」感を消す。

| 意図 | 実装 |
|---|---|
| 紙の上の気配 | `globals.css` の ambient グラデ + 粒（`prefers-reduced-motion` で停止） |
| セクション入場 | `<Reveal delayIndex={n}>`（60ms スタッガー） |
| リストの手触り | `.motion-row`（hover でわずかに浮く） |
| 進捗の生命感 | `ProgressRing` の arc draw / 連続日の soft pulse |
| ナビ | sticky + blur、下線が伸びる |

やりすぎない: 装飾アニメより **主従・余白・反復** が先（研修 FB 順）。

## 着手前（UI を触る前の5問）

1. **目的** — この画面でユーザーに何をしてほしいか（学ぶ / 仕分ける / 直す / 見る）
2. **一番** — ファーストビューで一番強く見せる情報は何か（1つだけ）
3. **構成の裁量** — セクション追加・並び替えはしてよいか
4. **既存トークン** — `ink` / `accent` / `surface` / `border` など既存 CSS 変数に乗るか
5. **媒体制約** — SP でも CTA・主要操作が押せるか（hover 前提にしない）

## 原則チェック（暗記セット）

| 原則 | 見るところ |
|---|---|
| 近接 | 関係要素の間隔 < グループ間の間隔か |
| 整列 | 同粒度で左/中央揃えが混在していないか |
| 反復 | 同じ役割（見出し・チップ・行）が同じ見た目か |
| コントラスト | 主従が中途半端ではなく明確か |
| 余白 | 壁張り付きがないか。空いているから足していないか |
| ジャンプ率 | タイトル / 本文 / 注釈のサイズ段差があるか |
| 視線 | 最初に見せたいものが最初に入るか |

## FB・セルフレビュー順（装飾から入らない）

1. 目的
2. 情報整理（順番・グルーピング）
3. 視線
4. 余白
5. 配色（色数・意味。増やす前に情報整理を疑う）
6. 装飾（最後）

指摘テンプレ: `〇〇のために、〇〇を、〇〇した／したい`  
例: 「仕分けに集中するために、キャプチャ行の余白をグループ間より狭くし、アクションを右に揃えた」

## Web / プロダクト UI の常識

- FV（または画面上部）で: 何の画面か / 誰向けか / 次に何をするか
- CTA・主要ボタン: 色差・十分な大きさ・周囲余白・行動が分かる文言
- 本文可読: PC 目安 16px 前後、SP 14px 以上（注釈は下回って可）
- 色は既存トークン優先。新規色を足すなら理由を書く
- 画像に文字焼き込み・フォント乱立・高さ固定で可変破綻は避ける

## あるある NG（Applied Loop でも起きやすい）

1. 全部目立たせて何も目立たない
2. 押せると分からないコントロール
3. 余白なし（壁張り付き）
4. 数 px のズレ・揃え混在
5. 色・フォント種類の増えすぎ
6. 行リストのトーンバラバラ（zinc 残骸と新トークンの混在）
7. 区切り線過多（余白で足りる）
8. ページ外枠の不統一

## AI の使い方

選択肢・比較・実装叩き台は AI。最終判断は人間。  
「おしゃれに」「なんか違う」は禁止。目的と原則に翻訳してから直す。
